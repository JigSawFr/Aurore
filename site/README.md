# The website

Aurore's website, on GitHub Pages: <https://aurore.boreale.dev/>. In the consoles' 15 languages, Aurore's own (`resources/i18n/`), as PlayGuard's and PlayShelf's sites: English at the root, the others each in its folder (`/fr/`, `/fr-ca/`, `/de/`, `/es/`, `/es-419/`, `/it/`, `/nl/`, `/pt/`, `/pt-br/`, `/ru/`, `/ja/`, `/ko/`, `/zh-hans/`, `/zh-hant/`); one dark look, Boréale's (the night, the aurora: [boreale/branding](https://github.com/JigSawFr/boreale/tree/main/branding)).

- **The home page**: what Aurore is, a screen in XML and its activity, the features, Cadran, the screenshots, the demo on each console (the simulated platforms: `.github/readme/console-<id>.png`, made by `capture.sh`, `CONSOLES` in `build_site.py`), what Aurore adds to borealis, under the hood (the versions and how the code is checked, read from the repository by `tools/stack.py` when the site is built, the README's section the same), how to use it in a project and build the demo, the apps made with it, the documentation, the licence.
- **Aurore and borealis** (`/borealis/`, `vs_body()` in `build_site.py`): everything Aurore adds to or changes from xfangfang/borealis' `wiliwili` branch, where it starts, under the home page's night: where Aurore comes from, the headline differences, what borealis does not have (cards), what both have side by side (a table, a card per line on a phone), the fixes and who they were picked from, the names an app changes (a diff, the guide [*Migrating from borealis*](../docs/migrating-from-borealis.md) for the rest), the project. Only what the code, its history and its docs show; in the header (not on a phone), the footer and the home page's "What Aurore adds".
- **Reading the documentation**: once the header is scrolled away, a slim bar at the top (the way home, the page's name, the search, the light reading); *Light reading* puts the documentation's pages on a light ground (kept as `aurore-reading`, `reading.js` setting it before the first paint); the search's field shows its key, `/`.
- **The footer** has a Boréale column (boreale.dev, PlayGuard, PlayShelf, Atlas, Lantern, the privacy and legal notice), and the menu of Boréale's sites shows the projects' versions, read from boreale.dev's `versions.json` at the build. The page not found stands under the aurora, as the home page's hero.
- **The home page's showcase** (site.css's and site.js's "showcase" blocks, the same on Boréale's four sites, PlayGuard's the reference): the demo on a console of our own (`.device`, its sides `DEVICE_GRIPS`), leaning towards the text on a wide screen; the screen in XML and its activity in an editor's window, a tab for each file, beside the screen they make drawn in HTML in Aurore's look (its button shows the activity's "Hello!"); the night going on down the page (veils of aurora, faint stars, a horizon over the footer); the features on tiles, their edge lit under the pointer; the sections rising into view once; on a wide screen, the screenshots as one large over a strip of the others; the steps joined by a line; a short cross-fade from one page to the next where the browser can. Without script, or with less motion asked, everything stays in place, both files of the editor one under the other.
- **The languages**: the header's button shows the page's language (its flag and name, its code on a tablet or a phone) and opens their menu, each with its flag, this page in each (a popover, as the menu of Boréale's sites). A first visit to the English home page goes to the browser's language when the site has it (`lang.js`, before the page is drawn: `fr-CA` for a Canadian French browser, `es-419` for a Spanish one outside Spain, `zh-Hant` for Taiwan, Hong Kong and Macao…); the language chosen in the menu is kept (`boreale-lang`, the folder it leads to, `en-US` for English; a choice kept before as `aurore-lang` moves there once, `reading.js`): once a language is chosen, the English home page no longer follows the browser's, an English page that has a translation (its `hreflang`) opens in the one chosen, at the same place (`#hash`), and the page not found shows it. Headings break as each script wants: Japanese between phrases, Korean between words, Chinese titles at their spaces and punctuation, no punctuation mark opening a line.
- **The documentation**: `docs/*.md`, converted at each build. It is written in English; every other language shows the same pages under its own header, saying so (PlayGuard's way for a page not translated), and the sidebar keeps the pages' English names. The code samples stay as they are, in every language; the drawn screen's welcome line is in the page's language. Links between the docs and to the README become the site's pages, any other file of the repository links to GitHub, GitHub's `> [!NOTE]` blocks become callouts, headings keep GitHub's anchors. A search box above the pages searches `docs/search.json`; `/` goes to it.
- **The API reference** in `/api/`: Aurore's public headers as Doxygen reads them (`docs/Doxyfile`, its XML), made into the site's own pages by `tools/build_api.py`: a home page sorting the API by theme, a page per namespace and per class or struct (`/api/aurore/View/`, `/api/cadran/kit/Chip/`), the index of every class, the macros, and its own search (`api/search.json`, `/` goes to it). The pages wear the site's English header, the API being in English as the headers; its language menu leads to each language's home page. Doxygen's old addresses (`classaurore_1_1View.html`) send their visitor on to the new pages.
- **The demo in a browser** ([web/README.md](../web/README.md)) in `/demo/`, which the home page and the header offer to try.
- **The changelog** (`/changelog/`, from `CHANGELOG.md`) and `releases.atom`.
- **The page not found** (`404.html`, served at any address), in the 15 languages, a `.not-found[data-lang]` block each: boreale-site's `lang.js` shows the address' (`/de/…`), else the one chosen in the header's menu, else the browser's.
- **For search engines and AI assistants**: absolute links, `sitemap.xml`, schema.org data, the preview image (`.github/branding/social-preview.png`), each page of the documentation in Markdown next to it, listed in [`llms.txt`](https://llmstxt.org) (`llms-full.txt`: all of it in one file).

## How it is made

`tools/build_site.py <out-dir>` (Python 3, Python-Markdown and PyYAML) writes the pages; no framework.

- **What Boréale's sites share** is [boreale-site](https://github.com/JigSawFr/boreale-site), the submodule `library/boreale-site`: the 15 languages (`LANGUAGES`, their flags and Open Graph locales), the header's two menus, the rules for links out and their UTM tags, the audience, the texts of the two menus (its `i18n/`), and the fonts, the marks (`marks/aurore.svg` is Aurore's: Boréale's drawing of its icon), `lang.js`, `umami.js`, `boreale.css` and `boreale.js`, copied into the built site's `assets/` (`boreale.copy_assets()`, which stops the build if `site/assets/` has one of them too). A change there reaches this site when the submodule moves (Dependabot opens the pull request).
- `site/i18n/<language>.json`: the texts around the content, one catalog per language, named by the app's code (`en-US.json` the reference, `fr.json`, `fr-CA.json`, `de.json`… `zh-Hant.json`); the menus' texts are boreale-site's, and a key of its catalogs here stops the build. They are HTML; `{{repo}}` is the repository's address. The names of screens and features follow the app's own catalogs (`resources/i18n/<language>/`); product names, files, code and commands stay as they are. French has a non-breaking space before `:` `;` `?` `!`, Canadian French before `:` only. A new visible text goes in all 15. A new language is a catalog here and in boreale-site (its line in `LANGUAGES`, its flag, its Open Graph locale, its folder in `lang.js`).
- `site/assets/`: `site.css` (loaded after boreale-site's `boreale.css`: Aurore's own colours over the brand's, its header, its pages), `site.js` (the aurora behind the home page, the screenshots' lightbox, the copy buttons, the search, the table of contents), `reading.js` (the light reading, before the first paint) and `api.css` and `api.js` (the API reference's own: its declarations, signatures and members). The fonts (Sora, Figtree, JetBrains Mono, SIL Open Font License; the language menu's 15 flags cut out of Twemoji's, CC-BY 4.0) are boreale-site's, served with the site so that no visitor's browser loads anything from anyone else. Cyrillic, Japanese, Korean and Chinese are drawn by the system's fonts.
- **Boréale's sites**, in a menu the header's name opens, the site's own leading home (boreale-site's `Site.switcher()` and `sites.json`, a popover the browser closes on Esc or a click elsewhere): boreale.dev, the homebrew, the integrations (Home Assistant), the libraries, the open data and protocols (Atlas, Lantern), each in the page's language: Boréale's sites have the same 15 folders (`fr/`, `fr-ca/`, `de/`… `zh-hant/`, English at the root), and the footer's links to boreale.dev, PlayGuard, PlayShelf, Atlas, Lantern and the legal notice go to the same folder. Its CSS and script are boreale-site's `boreale.css` and `boreale.js`, the marks its `assets/marks/`.
- The screenshots are the README's (`.github/readme/`), the icon and the preview image Aurore's (`.github/branding/`).
- The documentation's sidebar is `DOCS` in `build_site.py`: a new page of `docs/` is a line there.
- `SITE_URL` is the site's address; `SITE_NOINDEX=1` keeps a build out of search engines; `SITE_API=<folder>` publishes the API reference `tools/build_api.py` wrote there in `/api/` and links to it; `SITE_DEMO=<folder>` the demo built for a browser (`build-web/web/`) in `/demo/`.
- **The audience**, counted by Umami Cloud (<https://cloud.umami.is>): `assets/umami.js` (boreale-site's copy) is its tracker, served with the site, that sends each page seen to `gateway.umami.is`, without cookie, and only from the site's own address (`SITE_URL`'s, not a local copy); a pull request's build has none. Its site in Umami (boreale-site's `UMAMI_WEBSITE`) is Boréale's, shared with the other projects' sites: Umami's *Hostname* filter tells them apart. A link to another of our sites (boreale.dev, its other sub-domains) says where the visit comes from, for Umami's *UTM* report: boreale-site's `Site.links_out()` adds `utm_source=aurore` and `utm_medium=nav` (header), `footer` or `link` (the page's text); a link to aurore.boreale.dev itself loses the tags a documentation page was written with for GitHub (`utm_source=github`), in the pages and in the Markdown the site serves (`Site.untagged()`), and `tools/check_site.py` checks both. A link to `github.com/JigSawFr`, the account or its repositories, keeps the origin too (`referrerpolicy="strict-origin"`). The demo app's QR codes and *Website* button carry `utm_source=aurore-demo` (`utm_medium=qr`, `app`).
- A **Content-Security-Policy** on every page (a `<meta>`: GitHub Pages sends no headers): only the site's own files, no inline script or style; the one address it may send to is Umami's (`connect-src`).

To look at it locally:

```sh
git submodule update --init library/boreale-site   # what Boréale's sites share
python3 tools/build_site.py /tmp/site
python3 -m http.server -d /tmp/site 8000      # http://localhost:8000/
```

With the API reference: `doxygen docs/Doxyfile` (its XML in `build_docs/xml`), `python3 tools/build_api.py build_docs/xml build_api` (with `SITE_DEMO` too when the demo is published: its pages' header links to it), then `SITE_API=build_api python3 tools/build_site.py /tmp/site`.

## Checks

- `tools/check_site.py <site> [site-url]`: boreale-site's checks (`boreale_site.check.pages()` and `check_catalogs()`: no `{{key}}` left, links, `#anchors` into the same page or another and absolute links to the site that lead somewhere, links out and their UTM tags, nothing the Content-Security-Policy blocks, event handlers included, Umami's tracker, no e-mail address, the catalogs, its own included, with the same keys as `en-US.json`, English's notes that a page is in English left empty), the demo, built apart, left out; then Aurore's: no stylesheet from elsewhere, the JSON files read. A pull request's preview (`SITE_NOINDEX=1`) has no tracker, a page that only sends its visitor on neither tracker nor policy.
- boreale-site's `library/boreale-site/tools/site_layout.py <site>` (Playwright for Python), with the options of `site.yml`: every page on an iPhone, the API reference's included, the demo left out (`--skip demo`), the widest also on a small phone, a phone in landscape, a tablet and a desktop (`--wide`: the home page, the page on borealis, the documentation's widest, the changelog, in every language, long German and Russian words included, and the API reference's widest): none wider than the screen, no script that throws, no target under 24px (WCAG 2.2, 2.5.8: the headings' `#` links, the API's source lines), no field under 16px on a phone, and nothing axe-core finds against WCAG 2.2 AA (`SITE_AXE=<axe.min.js>`) on every English page and each language's home page (`--axe-english`).

## Publishing

`.github/workflows/site.yml` builds the demo for a browser, the API reference and the site, and runs both checks for each pull request (the `site` artifact) and for main, whose site it publishes on GitHub Pages.

In the repository's settings, *Pages › Build and deployment › Source: GitHub Actions*, with the custom domain `aurore.boreale.dev`; the workflow reads the address from Pages.
